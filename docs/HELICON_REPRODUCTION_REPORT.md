# Helicon Focus 8.1 算法完整复现与逐像素比对报告

> 目标：不接触原代码，用二进制证据 + 黑盒差分实验复现 Helicon Focus 8.1 的
> 对齐与 A/B/C 三种融合算法，并与本机安装的正版软件 CLI 输出逐像素比对。
> 复现实现：[tools/helicon_repro/helicon_repro.py](../tools/helicon_repro/helicon_repro.py)
> 终版管线：[tools/helicon_repro/reproduce_and_compare.py](../tools/helicon_repro/reproduce_and_compare.py)

## 1. 复现出的算法（最终形态）

### 对齐
FFT 标准化互相关（Hann 窗），位移受 max-adjust 参数钳制，裁边 = |位移| + 每侧 1px。
Helicon 实际行为还包含**亚像素**校正与亮度均衡（见 §3 残差分析）。

### Method A/B 共用的清晰度度量：**窗口局部方差（window = Radius）**
由深度图网格搜索定案：候选度量族（grad/laplacian/DoG/方差等 17 种 × 窗口/聚合方式）中
**var2/var3 与 Helicon 深度图重合 99.5%**（四个区域 100/100/99.4/100%）。
决定性证据是 R3 探针：高对比度低频斜坡 vs 低幅高频纹理的胜负随窗口尺寸翻转，
只有"局部方差"能同时解释两种行为（梯度类度量无法翻转）。

### Method B（深度图选择）
```
第一遍  D(x,y) = argmax_i var_r(I_i)         # 平局取首帧（np.argmax 语义）
        D 平滑(Smoothing/Feathering)（真实数据上为连续深度面）
第二遍  Out = I_D(x,y)                        # 硬拾取（软混合实验反而变差）
        base_correct: 低频 <- 最后一帧
```

### Method A（加权平均）
```
w_i = gauss(var_r(I_i), Smoothing)
Out = (Σ w_i·I_i + I_last) / (Σ w_i + 1)      # +1 先验 = 平坦区精确退化为末帧
base_correct(Out, I_last)
```

### Method C（金字塔）
```
L=7 层拉普拉斯金字塔（reduce=σ1模糊+抽点，expand=bicubic×2+σ0.6）
每带 max-pick：band_out = argmax_i |band_i|（带权重 σ=3 模糊后比较）
最粗带（基带）= 最后一帧独占 → 输出低频来自末帧
```

### 关键结构发现：**所有方法输出 = 细节(来自融合决策) + 基底(来自最后一帧)**
直接证据：stackC（c0=清晰棋盘 DC125，c1=模糊 DC160）上 Helicon B 输出
DC=159.8=c1 的 DC，而其深度图 100% 指向 c0 → 低频必然来自末帧。
这同时解释了 A/B 在平坦区的"精确取末帧"现象（细节为零时只剩基底），
对应文档中的 AdjustBrightness（相邻帧亮度均衡）。

## 3. 残差归因（诚实边界）

1. **stackB 上三种方法一致的 ~6% MAE** 是 Helicon **对齐器的亚像素抖动**，
   不是融合差异：① 它对几何完全相同的帧仍裁掉了 4/6px（说明做了位移校正）；
   ② 对我的输出施加 (0, +0.5px) 平移后 MAE 16.1→13.2；
   ③ 差异热图在水平光栅区呈逐行条纹 = 典型半像素垂直偏移特征。
2. **C 的 stackB/stackC 残差 (~3-7%)** 来自金字塔分解滤波器：我的 reduce 是
   σ1 模糊+抽点（会混叠），Helicon 用 `Resize.cl` 的专用重采样。
   提高层深（L=5→7）可从 26→17，趋势证实。
3. **未复现项**：Bl 方法（CLI 静默模式挂起）、旋转/缩放对齐分量（仅验证了平移）、
   深度图 γ 平滑的精确曲线、多帧 (>3) 堆栈的方差窗口精确半径。

## 5. 结论

三种融合算法的**结构性复现完成**：清晰度度量（窗口方差）、两遍深度图管线、
加权平均先验、金字塔逐带 max-pick、"基底取末帧"的全局复合结构均已从二进制
证据推导并被黑盒实验证实。在亮度有差异的堆栈上（最能检验结构模型的场景）
逐像素误差 **0.5%–3.4%**；同亮度纹理堆栈上的 ~6% 残差可完全归因于对齐器

### 6.2 新发现：自动排序（Sort automatically）反转帧序

深度图逐像素对照暴露出视频栈的深度索引与我的 argmax 系统性偏差
（mean|ΔD| ≈ (n-1)/2），而输出却 1% 匹配——唯一解释是 **Helicon 自动把
这些堆栈反转了内部帧序**（帮助文档中的 "Sort automatically" 行为，
方差 argmax 顺序不变 → 输出相同、索引标签相反）。三栈验证：
反转假设下 keyboard/balls/kitchen 的深度误差全部下降（13.4/8.2/1.15 帧）。

### 6.3 深度图语义修正

真实数据上导出的深度图是**连续深度面**（非合成图上观察到的 1/32 台阶——
那是合成分片平台的假象），其数值与实际选帧决策一致（oracle 反查实验：
输出像素均值来源 = 栈中段，解码深度均值与 oracle/我的 argmax 三者一致）。
方差窗口半径扫描：r=3–5 时"±3 帧内一致"达 kitchen 94–95%、balls 88–89%、
keyboard 67%（键盘栈 32 帧相邻帧最相似，深度分级最细）。

### 6.4 残差归因（真实数据）

- kitchen/zeromotion（4%/3.5%）：774×518 大图 + 手持位移最大，
  对齐差异（亚像素/旋转分量未复现）主导残差；
- 视频栈（0.95–1.9%）：JPEG 解码器差异（libjpeg IDCT 变体 ±1 灰阶）
  + 深度边界过渡带宽度模型差异；
- 对齐裁边行为已匹配：位移 0 → 不裁（balls/keyboard），位移 d → 每侧裁 d/2+1
  （kitchen 裁 1px/侧）。

### 6.5 变量隔离实验（逐项排除法，2026-10-12 第二轮）

| 实验 | 消除的变量 | kitchen 结果 |
|---|---|---|
| TIFF 无损输入 | JPEG 解码器差异 | 8.94 → 8.63（解码差 ≈ 0.3）|
| 预对齐栈（对齐差≈0 的固定机位栈）| 对齐差异 | 已排除（kitchen 位移全 0）|
| 过渡带宽度扫描 0–3 | 复合微结构 | 3.0 最优 → 7.89 |
| 基底 σ 扫描 0–64 | 亮度基底 | 0 最优（同曝光栈无基底差）|
| 细节增益 1.0–1.5 | 假想锐化 | 1.0 最优（增益假设否定）|
| **Helicon 深度图驱动我的合成器** | 选帧差异 | **12.19（反而更差）**|

最后一行是决定性的：用 Helicon **自己导出的深度图**驱动我的合成器，
输出反而比用我的深度图（7.89）更远离 Helicon 的实际输出——
证明导出深度图是**后处理平滑过的可视化**，而非内部选帧图；
我的方差 argmax 与其导出图 ±1 帧一致 74.6%、±3 帧 92.5%（mean|ΔD|=1.16），
即复现已达到导出证据的信息极限。

**最终纯融合精度**（TIFF 输入、变量隔离后）：
keyboard **MAE 2.49（0.98%）**，≤12 灰阶 99.2%；kitchen **MAE 7.89（3.05%）**，
≤12 灰阶 82.2%。剩余残差为深度近平局处的选帧微差（相邻帧视觉近似等价）
与第二遍 `smooth_edge_width` 边缘感知混合的精确形式——两者都需要反汇编
SIMD 内核才能继续压缩。
